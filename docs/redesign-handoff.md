## ขั้นที่ 1 — โครงหน้าร่วม (ทุกหน้าใช้)

### 1.1 เมนูเป็นแท็บด้านบน แทนแถบซ้าย
- ลบ `<aside class="side">` ใน `public/index.html` และสไตล์ `.side`, `.nav-edge`, `.nav-toggle`, `nav-pin`/`nav-peek` ที่เกี่ยวข้อง
- ทำแถบหัว (header) สี `--side-bg` สูงประมาณ 64px: โลโก้ขาว (`assets/hea-logo-white@2x.png` กว้าง 72px) · แท็บ 7 หน้า · ปุ่มธีมชิดขวา
- ลำดับแท็บ (ต้องตรงตามนี้):
  1. Executive Snapshot (`#snapshot`)
  2. รายได้ตามกลุ่มลูกค้า (`#revenue`)
  3. การใช้น้ำเทียบปีก่อน (`#usage`)
  4. ยอดขายและการใช้น้ำ (`#sales`)
  5. ลูกค้า (`#customers`)
  6. การจัดเก็บและลูกหนี้ (`#collections`)
  7. การจดมาตร (`#meter`) — ขั้นที่ 8
- แท็บที่เลือก: ตัวหนา 600 + เส้นใต้ 3px สี `--hea-aqua` · ใช้ `aria-current="page"` เหมือนเดิม (โค้ดใน `render()` ใช้ได้ต่อ ถ้าแท็บยังอยู่ใน `#nav` และมี `data-page`)
- จอแคบ แท็บตัดขึ้นบรรทัดใหม่ได้ (`flex-wrap`)
- ชื่อบริษัทไทย/อังกฤษที่เคยอยู่ท้ายแถบซ้าย ย้ายไปไว้ใน footer

### 1.2 ปุ่มธีม
- ใช้ `public/theme.js` เดิม (อัตโนมัติ / สว่าง / มืด) แค่ย้ายปุ่ม `.seg` ไปไว้ในแถบหัว
- บนพื้น Navy: ปุ่มที่เลือกพื้น `--hea-aqua` ตัวอักษร `--hea-deep-navy` · ปุ่มอื่นพื้นโปร่ง ตัวอักษรขาว

### 1.3 หัวหน้า + ตัวกรองแถวเดียว
- แทนที่ `.top` + `.filters` เดิม ด้วยแถวเดียว: ซ้ายคือชื่อหน้า (24px/600) + บรรทัดเล็ก `SNAPSHOT · ข้อมูล ณ … · ที่มาของข้อมูล` · ขวาคือ select ตัวกรอง (label 12px เหนือช่อง) + ลิงก์ "ล้างตัวกรอง"
- ตัวกรองแต่ละหน้าแสดงเฉพาะที่มีผลกับหน้านั้น (ใช้ข้อมูลเดียวกับ `#fx-body` "ตัวกรองมีผลกับอะไร" เพื่อซ่อนตัวที่ไม่มีผล)
- ชื่อแอป "HEA Sales Executive Dashboard" ไม่ต้องแสดงซ้ำเป็น h1 ใหญ่ทุกหน้า (ใส่ใน `<title>` พอ)

### 1.4 การ์ด KPI แบบใหม่ — แก้ฟังก์ชัน `kpi()` (app.js ประมาณบรรทัด 282)
- โครง: ชื่อ (13px/500 `--text-2`) + ปุ่ม ⓘ ชิดขวา → ตัวเลข 30px/600 + หน่วย → แถวเปรียบเทียบ 1–2 แถว (ซ้าย = คำอธิบาย, ขวา = ค่าสี good/bad)
- **ข้อความยาวเดิม (`sub`) ย้ายไปไว้ใน `title` ของปุ่ม ⓘ** ไม่แสดงใต้ตัวเลขอีก — ส่วนนี้คือหัวใจของ "ดูไม่รก"
- `cmpPill()` เดิมยังใช้ได้ในแถวเปรียบเทียบ
- การ์ดที่สำคัญที่สุดของแถวใช้ขอบบน 4px `--accent` (คลาส `accent` เดิม) · การ์ดที่เป็นเรื่องเสีย (เช่น ลูกหนี้เกินกำหนด) ใช้ขอบบนสี `--status-bad`
- แถว KPI ใช้ `grid-template-columns: repeat(auto-fit, minmax(240px, 1fr))` (หน้า Snapshot ใช้ 170px เพราะมี 7 ช่อง)

### 1.5 การ์ดทั่วไปและกล่องที่มาข้อมูล
- `card()` เดิมใช้ต่อได้ หัวการ์ด: ชื่อ 16px/600 `--heading` + คำอธิบายบรรทัดเดียว 13px · ปุ่ม "ตาราง"/"CSV" ชิดขวา
- ย้ายข้อความ "ตัวกรองที่มีผล…" ใต้การ์ด (`.applies`) ไปไว้ใน `title` ของหัวการ์ด เพื่อลดบรรทัด
- กล่อง `#fresh` (SNAPSHOT · สำรองฐานข้อมูล… · ดึงข้อมูล…) อยู่ท้ายทุกหน้าเหมือนเดิม
- ระยะห่างระหว่างการ์ด 16px ทุกที่ · คู่การ์ดใช้ `display:flex; flex-wrap:wrap` กับ `flex: <น้ำหนัก> 1 <ความกว้างต่ำสุด>px` แทน `.g2/.g3` เพื่อให้สัดส่วนไม่เท่ากันได้ (เช่น กราฟ 2 ส่วน : การ์ดข้าง 1 ส่วน)

### 1.6 ตาราง
- หัวตารางกลุ่มคอลัมน์ (`.grp-t`) ใช้ต่อ · แถวรวมย่อยพื้น `--subtle-bg` · แถว "รวมรายได้ขายน้ำ" ใช้ `tr.water` เดิม
- คอลัมน์ YoY/เปลี่ยนแปลงใช้ pill เดิม
- คอลัมน์ "สัดส่วน" หรือ "ผลต่าง" ที่ต้องเทียบขนาด เพิ่มแถบเล็ก (div สูง 10px กว้างตาม %) ข้างตัวเลข

## ขั้นที่ 2 — Executive Snapshot (`pSnapshot`)

เป็นหน้าแรก (ภาพรวมผู้บริหารเดิมที่ซ่อนไว้ ไม่ต้องเปิดกลับ)

1. หัวหน้า: "Executive Snapshot · รายได้ประจำเดือน <เดือน>" + ตัวกรองเดือนรายงาน/สาขา/ประเภทลูกค้า + ปุ่ม "พิมพ์ / บันทึก PDF (2 หน้า)" (ปุ่มเดิม)
2. KPI 7 ช่อง: รายได้เดือน (พื้น `--target-bg`), ลูกค้าทั่วไป, ปริมาณน้ำ, ราคาเฉลี่ยต่อหน่วย, YTD, ประมาณการทั้งปี และ **เพิ่ม "ลูกหนี้ค่าน้ำคงค้าง"** (ค่าจาก `arAgg()`: คงค้าง, เกินกำหนด + %, เกิน 90 วัน) พร้อมลิงก์ "ดูหน้าการจัดเก็บและลูกหนี้ →"
   - แต่ละช่องแสดง MoM/YoY เป็นแถวเปรียบเทียบ (ไม่ใช่ข้อความยาว)
3. การ์ด "รายได้ตามกลุ่มลูกค้า": ตารางเดิม จัดหัวคอลัมน์เป็น 3 กลุ่ม — เดือนนี้ (ล้านบาท, MoM, YoY, บาท/ลบ.ม.) · สะสม (ล้านบาท, YoY, สัดส่วน) · ต่อรายและแนวโน้ม (บาท/ราย/เดือน, sparkline, 3 เดือนล่าสุด) · แถว "รวมทั้งหมด" เส้นบนล่าง 2px `--accent`
4. แถวถัดไป: กราฟ "รายได้รายเดือนแยกกลุ่ม" (กว้าง 2 ส่วน, แถบฤดูฝนและจุดแล้งเดิม) คู่กับการ์ด "ฤดูกาลและภัยแล้ง" (ดัชนี 12 เดือนเป็นตาราง 6×2 + ข้อความสรุป 1 บรรทัด + กล่องเตือนแล้งสีเหลือง)
5. แถวสุดท้าย: "สิ่งที่ต้องทำ" (จาก `actionPlan()` 4 ข้อแรก) เป็นรายการมีเลข + ป้ายด่วน/สำคัญ + ผู้รับผิดชอบชิดขวา คู่กับการ์ด "แนวโน้ม 3 เดือนล่าสุด" (กล่องเขียว "▲ ดีขึ้น" กับกล่องแดง "▼ แย่ลง" + 2 ประโยคสรุป)
6. การพิมพ์ 2 หน้า A4 แนวนอนต้องยังทำงาน

## ขั้นที่ 3 — รายได้ตามกลุ่มลูกค้า (`pRevenue`)

เรียงใหม่จากบนลงล่าง:
1. KPI 4 ช่อง (เดิม) — ช่อง "รายได้ไม่รวม กปภ." เป็นช่องเน้น (ขอบบน accent)
2. **ย้าย Insight + ข้อเสนอแนะ (`c-ins`, `c-rec`) ขึ้นมาไว้ต่อจาก KPI** วางคู่กัน · ข้อเสนอแนะแต่ละข้อมีป้ายผลกระทบสีเขียวชิดขวา (เช่น "+3.35 ล้าน/ปี")
3. ตาราง `c-rev`: แสดงเงินเป็น **ล้านบาท 2 ตำแหน่ง** (CSV ยังเป็นบาทเต็ม) · ป้าย "⚠ ไม่มีบิล N เดือน" ของ กปภ. เดิม
4. คู่กราฟ:
   - `c-revbar` เปลี่ยนเป็น **แท่งแนวนอน** 2 แท่งต่อกลุ่ม (2568 สีอ่อน, 2569 สีเข้ม) ชื่อกลุ่มอยู่ซ้าย ไม่ต้องเอียง
   - `c-pu` แท่งแนวนอนเรียงมากไปน้อย + เส้นประค่าเฉลี่ย · **แท่งที่ต่ำกว่าค่าเฉลี่ยใช้สีส้ม**
5. **รวม `c-mix` กับ `c-mixt` เป็นการ์ดเดียว** มีปุ่มสลับ "กราฟ / ตาราง" · ใต้กราฟใส่ประโยคสรุป (เช่น "T3 มีลูกค้า 2.2% แต่สร้างรายได้ 43.5%")
6. `c-brg` ตำบลไม้ขาวและตำบลสาคูวางคู่กันซ้าย-ขวา · ยอดรวมและ YoY อยู่ที่หัวแต่ละตาราง · เงินเป็นล้านบาท
7. `c-moo` คอลัมน์ YoY เพิ่มแถบแยกซ้าย (แดง = ลด) / ขวา (เขียว = เพิ่ม) จากเส้นกลาง ตัดที่ ±50%

## ขั้นที่ 4 — การใช้น้ำเทียบปีก่อน (`pUsage`)

1. KPI 4 ช่อง (เดิม) — "ลูกค้าทั่วไป ก.ค.–ต.ค." เป็นช่องเน้น · ตัวเลข "ใช้น้ำลดลง" สีแดง "เพิ่มขึ้น" สีเขียว
2. กราฟ `c-qd` เดิม (แท่งซ้อน + เส้นปีนี้ + เส้นประปีก่อน + ปุ่มสลับปริมาณน้ำ/รายได้ + ชิป YoY) · เพิ่มประโยคสรุปใต้กราฟ 1 บรรทัด
3. คู่การ์ด:
   - `c-qst` ตารางการเปลี่ยนแปลงการใช้น้ำ (เดิม) ชื่อกลุ่มเป็นป้ายสี
   - **ใหม่: "ที่มาของปริมาณน้ำที่เปลี่ยนไป"** กราฟน้ำตกแนวนอน: ปีก่อน → +ใช้เพิ่ม → ±ใกล้เคียง → −ใช้ลด → +ลูกค้าใหม่ → −หยุดใช้ → ปีนี้ (คำนวณจากแถวของ `c-qst` ไม่ต้องเขียน SQL ใหม่)
4. `c-qdecl` 20 อันดับ: เพิ่มเลขลำดับ + แถบแดงตามขนาดผลต่าง · คำอธิบายใต้หัวเปลี่ยนเป็น "ฝ่ายกลยุทธ์ควรติดต่อสอบถาม" (ขั้นที่ 9)
5. `c-aud` ตรวจทะเบียน: เพิ่มชิปสรุปที่หัวการ์ด ("ใช้งานแต่ไม่มีบิล N" สีเหลือง, "งด/ยกเลิกแต่ยังออกบิล N" สีแดง)

## ขั้นที่ 5 — ยอดขายและการใช้น้ำ (`pSales`)

1. **KPI เป็น "สะพานตัวเลข"**: ก่อนส่วนลด − ส่วนลด − ใบลดหนี้ = ยอดขายสุทธิ (มีเครื่องหมาย − และ = ตัวใหญ่สีจางระหว่างช่อง) · ช่องสุทธิพื้น `--target-bg` · ใบลดหนี้ตัวเลขสีแดง
2. คู่กราฟ `c-comp` (ใบลดหนี้อยู่ใต้เส้น 0) และ `c-units` (เดิม)
3. คู่ตาราง:
   - `c-type` เงินเป็นล้านบาท + แถบสัดส่วน
   - `c-dma` เงินเป็นล้านบาท + แถบยอด (สีตามสาขา: น้ำเงิน = ไม้ขาว, เขียว = สาคู) + **คอลัมน์ใหม่ บาท/ลบ.ม.** = ค่าน้ำสุทธิ ÷ ลบ.ม. (คำนวณฝั่งหน้าเว็บ)
4. `c-top` 15 ราย: เงิน 12 เดือนเป็นล้านบาท · ค้างชำระเป็นบาท (0 แสดง "–") · คำเตือนของแถว (กปภ., ทะเบียนหอถังเดิม) เป็นกล่องเหลืองใต้ชื่อ · ค้างชำระเกิน 1 ล้านบาทเป็นสีแดง

## ขั้นที่ 6 — ลูกค้า (`pCustomers`)

1. KPI 4 ช่อง (เดิม) — "ลูกค้าที่ออกใบแจ้งหนี้ค่าน้ำ" เป็นช่องเน้น
2. คู่กราฟ `c-act` (เส้นแยกสาขา + ตัวเลขเดือนล่าสุดท้ายเส้น) และ `c-new` (เดิม)
3. คู่การ์ด:
   - `c-st` สถานะทะเบียน: ครบ 4 สถานะ + แถวรวม + แถบสัดส่วนสถานะในแต่ละแถว · ถ้ายกเลิกเกิน 30% ของประเภทนั้น ตัวเลขเป็นสีแดง + ประโยคสังเกตใต้ตาราง
   - `c-pipe` สรุป: ตัวเลขใหญ่ 3 ตัว (ค้างทั้งหมด, เกิน 60 วัน, ติดตั้งเสร็จเฉลี่ย/เดือน) + แถบตามสถานะ 3 แถว (กำลังดำเนินการ / รอดำเนินการ / อนุมัติแล้วรอติดตั้ง) แบ่งส่วนเกิน 60 วันเป็นสีแดง
4. ตารางรายละเอียดคำร้อง (ข้อมูลเดิมของ `c-pipe`) แยกเป็นการ์ดเต็มความกว้าง: เพิ่มแถบอายุเฉลี่ยพร้อมเส้นประที่ 60 วัน + ป้าย "⚠ N" ในคอลัมน์เกิน 60 วัน
5. `c-decl` รายการเฝ้าระวัง: แถบแดงตาม % ที่ลด · คำเตือนของแถวเป็นกล่องเหลืองใต้ชื่อ

## ขั้นที่ 7 — การจัดเก็บและลูกหนี้ (`pCollections`)

1. KPI 4 ช่อง (เดิม) — ยอดรับชำระเป็นช่องเน้น · **"ลูกหนี้ค่าน้ำเกินกำหนด" ขอบบนแดง ตัวเลขแดง** + แถว "จากคงค้าง X (Y%)" และ "ใบค้าง / ลูกค้า"
2. คู่กราฟ `c-coll` (เดิม) และ `c-ratio` (เพิ่มป้ายตัวเลข % เหนือทุกจุด · เส้นประที่ 100% · ชื่อเดือนที่มี ⚠ เป็นสีเหลือง)
3. คู่การ์ด:
   - **รวม `c-ar` + `c-arch` เป็นการ์ดเดียว** "อายุลูกหนี้": บนเป็นแถบแยกสาขา 2 แถว (สเกลเดียวกัน) ล่างเป็นตารางช่วงอายุเดิม · คอลัมน์ "ในนี้จากระบบเดิม" ที่ไม่ใช่ 0 เป็นสีเหลือง
   - `c-ch` ช่องทางรับชำระ: เงินเป็นล้านบาท + แถบ + % · ประโยคสังเกต 1 บรรทัด
4. `c-cohort` เต็มความกว้าง: คอลัมน์ "อัตราเก็บได้" เป็นแถบซ้อน (ตรงเวลา = น้ำเงิน, ช้า = ฟ้า, ค้าง = ว่าง) + ตัวเลข · อัตราต่ำกว่า 80% สีแดง · ค้างตั้งแต่ 1 ล้านบาทสีแดง · รุ่นล่าสุดเขียน "(ยังไม่ครบกำหนด)" ต่อท้าย
5. `c-debt` 10 ราย: คอลัมน์ 1–30/31–60/61–90 รวมเป็น **แถบเล็กแยกตามอายุ** เหลือคอลัมน์ "> 90 วัน" เป็นตัวเลข (สีแดง) · **"ครบกำหนดเก่าสุด" ก่อนปีปัจจุบันเป็นสีแดง**

## ขั้นที่ 8 — หน้าใหม่: การจดมาตร (`pMeter`)

**ที่มา:** CEO อยากดูความคืบหน้าการจดมาตรโดยไม่ต้องเข้า WMS · ตัวเลขในหน้า design มาจาก "แผงควบคุมงานอ่านมาตร" ใน WMS รอบ 01/10/2569–31/10/2569

### กติกาธุรกิจ
- เริ่มจดมาตรวันที่ **20** ของเดือน
- ต้องจด **ครบภายในวันสิ้นเดือน** เพื่อออกใบแจ้งหนี้และรับรู้รายได้ในเดือนนั้น
- **ดีเลย์ (วัน) = วันอ้างอิง − วันสิ้นเดือนของรอบ** (ถ้าบวก = เลยกำหนด)
- **ป้ายเตือน:** เหลือ ≤ 3 วันก่อนสิ้นเดือนแต่ยังค้าง = เหลือง "ใกล้ครบกำหนด" · เลยสิ้นเดือน = แดง "+N วัน" (เกณฑ์ 3 วันรอยืนยันกับคุณวิชาญ)

### นิยาม (ตาม WMS)
- **ทะเบียน** = ผู้ใช้น้ำสถานะ "ใช้งานปกติ" ณ วันสิ้นรอบ
- **อ่านแล้ว** = ทะเบียนข้างต้นที่มีรายการจดหน่วยน้ำในรอบ (ไม่ยกเลิก) นับ 1 ครั้งต่อทะเบียน
- **ค้างอ่าน** = ทะเบียน − อ่านแล้ว
- **หน่วยน้ำผิดปกติ** = อ่านแล้วแต่หน่วยเกิน 200% หรือต่ำกว่า 20% ของค่าเฉลี่ย 3 เดือนก่อน (ต้องมีประวัติครบ 3 เดือน และค่าเฉลี่ย > 0)
- **กระทบยอดใบแจ้งหนี้:** ใบแจ้งหนี้ค่าน้ำในรอบ = อ่านแล้วและออกใบ + อ่านแล้วแต่ทะเบียนไม่อยู่สถานะใช้งาน + ไม่มีการจดในรอบ (สร้างใบเอง/นำเข้า) · และต้องแสดง "อ่านแล้วแต่ยังไม่มีใบแจ้งหนี้" (ควรเป็น 0)

### ข้อมูลที่ต้องเขียน SQL ใหม่ — `sql/16_meter_reading.sql`
**ยังไม่รู้ชื่อตาราง:** ไม่มีไฟล์ไหนใน `sql/01–15` อ่านตารางบันทึกการจดหน่วยน้ำ ต้องหาในฐาน `hea_uat` ก่อน เช่น ตารางที่หน้า "แผงควบคุมงานอ่านมาตร" ของ WMS ใช้ หรือถาม vendor (Compattana) **อย่าเดาชื่อตาราง** ต้องการข้อมูลต่อรอบเดือน:
1. สรุป: ทะเบียน, อ่านแล้ว, ค้างอ่าน, ผิดปกติ, จำนวนใบแจ้งหนี้ค่าน้ำ และตัวเลขกระทบยอดตามข้อบน
2. **รายการค้างอ่าน (รายทะเบียน):** ทะเบียน, ชื่อ (ปิด PDPA ผ่าน `vw_dash_customer_waters` แบบไฟล์อื่น), พื้นที่การอ่านมาตร, พนักงานที่มอบหมาย
3. **ความคืบหน้ารายวัน:** จำนวนทะเบียนที่จดสะสมตามวันที่จด ตั้งแต่วันที่ 20 ถึงสิ้นเดือน
4. **ตามพื้นที่:** ทั้งหมด, จดได้, ค้าง, ถูกตัดมาตร, ออกใบแจ้งหนี้
5. **ตามพนักงาน:** เส้นทางที่มอบหมาย, อ่านแล้ว, คงเหลือ
6. **หน่วยผิดปกติ:** วันที่จด, เลขเดิม/ใหม่, หน่วย, ค่าเฉลี่ย 3 เดือน, % (ไม่ต้องเอาทั้ง 466 ราย ให้แสดง 10–20 รายแรก + ลิงก์ไป WMS)

เพิ่มชุดข้อมูลนี้ใน `server/server.js` (`/api/ds/meter`) และ `server/snapshot.js` แบบเดียวกับชุดอื่น · ใช้พารามิเตอร์ `$1`/`$2` รูปแบบเดิม

### หน้าตา (ดูหน้า "7 · การจดมาตร" ในหน้า design)
1. **แถบสถานะใหญ่ (พื้น Navy):** ประโยคเดียวตอบว่า "จดครบไหม · ค้างกี่ราย · ดีเลย์กี่วัน" + ป้ายสถานะขวา + แถบ % + ไทม์ไลน์ (เปิดรอบ 1 → เริ่มจด 20 → วันนี้ → ครบกำหนดสิ้นเดือน)
   - ระหว่างรอบ: "เหลือ N วัน — จดแล้ว X% (ช้า/เร็วกว่าแผน Y%)" + "ต้องจดอีกราว Z ทะเบียน/วัน" · แผน = เส้นตรงจาก 0% วันที่ 20 ถึง 100% วันสิ้นเดือน
   - ปิดรอบแล้ว: "จดครบ X% — เหลือ N ทะเบียน" + ป้ายแดง "เลยกำหนด D วัน"
2. KPI 4 ช่อง: จดแล้ว / ทะเบียน, ค้างจด (แดง), ออกใบแจ้งหนี้, หน่วยผิดปกติ (เหลือง)
3. คู่การ์ด: "ทะเบียนที่ยังไม่ได้จด" (ป้ายดีเลย์ต่อแถว เรียงจากดีเลย์มากไปน้อย) และ "จากจดมาตร ถึงรับรู้รายได้" (ขั้น 1–3 + กล่องเขียวเมื่ออ่านแล้วไม่มีบิล = 0)
4. คู่การ์ด: "ความคืบหน้ารายวัน" (แท่ง % สะสมวันที่ 20–31 + เส้นประแผน · ต่ำกว่าแผนเป็นสีส้ม) และ "ตามพื้นที่" (พื้นที่ที่ค้างขึ้นก่อน)
5. คู่การ์ด: "พนักงานอ่านมาตร" และ "หน่วยน้ำผิดปกติ"
6. กล่องกติกาและนิยามท้ายหน้า
